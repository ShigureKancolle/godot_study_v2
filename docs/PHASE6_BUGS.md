# 阶段 6 战斗 BUG 记录

记录日期：2026-09-06。

以下五项对应阶段 6 检查中的第 1、2、3、4、8 项，均为已知问题，暂缓修复。本文件仅记录现象、影响和后续验收条件，不代表已经修改实现。

## BUG-6-01：攻击者死亡或移除后，待结算攻击未取消

- 状态：待修复。
- 位置：`server/game/systems/comp_system.py` 的 `AttackCompSystem.update()`、`_get_attack_hits()`。
- 现象：攻击开始后、判定帧前，攻击者死亡仍可造成伤害；攻击者被移除则在获取组件时触发 `NoneType` 异常。
- 影响：死亡实体仍能结算此前的攻击；异常后该攻击的形状已被标记为处理，但攻击记录没有从队列清除。
- 后续完善：判定帧重新检查攻击者是否存在、是否存活，取消并清理失效攻击。
- 验收：攻击开始后死亡或断线，未结算攻击不再造成伤害，不报异常、不残留队列，也不影响其他实体攻击。

## BUG-6-02：攻击转向请求可以控制其他实体

- 状态：待修复。
- 位置：`server/protocol/handlers/combat_handler.py` 的 `atk_rotate_intent_handler()`。
- 现象：构造 `AtkRotateCommand` 时直接使用请求中的 `entity_id`，没有从当前连接推导受控实体。
- 影响：已登录客户端可以指定其他玩家或敌人，修改其攻击朝向。
- 后续完善：以连接绑定的 `player_entity_id` 为控制对象，并处理未进入游戏或受控实体失效的情况。
- 验收：伪造其他实体 ID 无法修改其朝向；正常玩家仍可控制自己的朝向。

## BUG-6-03：战斗能力和阵营配置未参与规则校验

- 状态：待修复。
- 位置：`server/game/systems/comp_system.py` 的 `AttackCompSystem`。
- 现象：攻击、命中和死亡流程没有应用 `can_attack`、`can_be_hurt`、`can_die` 以及 `attack_mask/hit_layer`。
- 影响：玩家可以伤害队友；具备组件但配置禁止攻击、受伤或死亡的实体，仍可能进入相应流程。
- 后续完善：攻击开始检查攻击能力，命中检测按受伤能力与阵营过滤，死亡处理遵循死亡能力配置。
- 验收：玩家只能命中配置允许的目标；禁止攻击、受伤、死亡的配置分别生效。

## BUG-6-04：扇形攻击错误调用矩形碰撞函数

- 状态：待修复。
- 位置：`server/game/systems/comp_system.py` 的 `AttackCompSystem._get_attack_hits()`。
- 现象：创建攻击形状后统一调用 `intersect_rect_circle()`；攻击 1001、1002、1003 为扇形，有候选目标时会因缺少 `distance` 属性而报错。
- 影响：默认矩形攻击 1004 可正常结算，但已配置的扇形攻击无法正常命中，失败攻击记录还可能残留。
- 后续完善：按形状分派碰撞判定；对不支持的形状明确拒绝，并保证失败攻击被清理。
- 验收：矩形与扇形攻击分别通过范围内、范围外、边界和朝向测试，异常配置不会遗留攻击记录。

## BUG-6-05：重复攻击请求缺少请求级去重

- 状态：待修复，对应检查中的第 8 项。
- 位置：`protocol/game.proto` 的 `AttackIntent`、`server/game/commands.py` 的 `AttackCommand`、`AttackCompSystem.apply_command()`。
- 现象：只有冷却校验，没有用于区分一次请求的序号或标识；同一请求在冷却结束后重放，会被当作新攻击。
- 影响：能够拒绝冷却期间的重复请求，但尚不能保证同一逻辑请求始终只结算一次。
- 后续完善：明确请求标识、去重范围及生命周期，拒绝重复或过期请求；协议变更通过项目同步脚本生成双端代码。
- 验收：同一请求在同 tick、冷却期间和冷却结束后重复提交，均只产生一次攻击；新的合法请求仍正常执行。
